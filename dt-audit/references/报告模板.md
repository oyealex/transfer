### 3.4 术语与判定说明

#### 3.4.1 术语

| 词 | 定义 |
|---|---|
| 逻辑点 | 本次改动引入或修改的一条行为分支。全篇的计量单位，3.3 一行一个。 |
| 用例 | 新增 / 修改 / 既有的测试方法；「覆盖用例」与 2.2 名单的计量单位。 |
| 分支的结果 | 这条分支做成的那件事：返回值、抛出的异常、写入的状态、发起的协作、产出的产物。判定时先写一句，再看断言有没有核对它。 |
| 关联 | 两件事：用例能不能执行到某个逻辑点，以及它的断言有没有核对到这个点的结果。只追一层入口；判不清记「不确定」，不记「未覆盖」。 |
| 有效 | 至少一条覆盖它的用例，断言核对到了这条分支的结果。 |
| 未覆盖 | 没有任何用例能执行到这条分支。 |
| 无效 | 有用例执行到了，但断言没核对该分支的结果，或跑的是假实现。 |
| 低价值 | 断言引用了结果，但只判非空、大小、类型、长度这类形态。 |
| 不确定 | 证据不足，判不出上面任一类。 |
| 新增 DT 密度 | 新增用例数 ÷ 变更生产代码 KLOC。 |

#### 3.4.2 问题分类与原因

五类判定结果里，**未覆盖、无效、低价值是问题类**；有效不是问题；不确定是证据状态，单列。「3 类问题中命中 N 类」只数这三类。

| 分类 | 说明 | 原因 |
|---|---|---|
| 未覆盖 | 这条分支没人测 | 无对应用例；**原有用例不再执行** |
| 无效 | 测了，但拦不住 | 无断言；断言没看这个点的结果；只验交互；只测假实现；断言镜像实现；**断言被注释** |
| 低价值 | 测了，但只核对形态 | 只判形态；**断言被弱化** |
| 不确定 | 看不清，不能判 | 证据不足；断言归属判不清；结构不可解析 |

原因只解释「为什么归这一类」，不单独计数。加粗的三条方向原因——原有用例不再执行、断言被注释、断言被弱化——表示「这次改坏的」，说明里必须写清被改动的文件与行号。

#### 3.4.3 定性规则

分母一律是全部逻辑点，按下列顺序判定，命中即止：

| 顺序 / 码 | 取值 | 条件 |
|---|---|---|
| 0 · R0 | 证据不足（前置） | 没有变更单元，或全部变更单元都是「无法获取」 |
| 1 · R1 | 合格 | 逻辑点 = 0 |
| 2 · R2 | 证据不足 | 不确定 > 40% |
| 3 · R3 | 待改进 | 未覆盖 ≥ 30%，或无效 ≥ 30%，或有效 < 50% |
| 4 · R4 | 优秀 | 有效 ≥ 75%、未覆盖 = 0、无效 = 0、不确定 ≤ 10%，且逻辑点 ≥ 8 |
| 5 · R5 | 合格 | 其余 |
