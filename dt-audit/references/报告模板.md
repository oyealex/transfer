#### 3.4.1 术语与指标（全篇的计量口径）

| 词 | 定义 |
|---|---|
| 逻辑点 | 本次改动引入或修改的一条行为分支。全篇的计量单位，3.3 矩阵一行一个。 |
| 产出项 | 一条分支正常执行产生的结果，只从五类里取：返回值、抛出的异常、写入或改变的状态、发起的协作、产出的产物。 |
| 决定性产出项 | 改错它业务就错的产出项。断言读到任一项即算覆盖，不要求每项都被断言。 |
| 断言覆盖率 | （已断言 + 断言偏弱）÷ 全部逻辑点。有断言在执行到的那部分逻辑点上的占比。 |
| 有效断言率 | 已断言 ÷ 全部逻辑点。断言读到分支决定性产出项、真能挡住缺陷的那部分占比。 |
| 实现被替换率 | 实现被替换 ÷ 全部逻辑点。真代码被探针 / 桩 / Mock 换掉的那部分占比。 |
| 证据完整度 | 可判定 ÷ 全部逻辑点。衡量「看得到多少」，不衡量质量。 |
| 证据完整度档 | ≥90% 完整、≥60% 较完整、其余不完整。 |
| DT | 设计测试（design test），本报告审计的对象。 |
| 新增 DT 与密度 | 新增 DT = 新增的测试方法数；密度 = 新增 DT 数 ÷ 变更生产代码 KLOC。 |
| KLOC | 变更生产代码的新增行数 ÷ 1000，只算 Java / Python 的生产文件。 |
| 用例变更类型 | 新增 / 修改 / 既有；只有前两类进断言条数统计，既有用例的断言可作为状态证据，但不进有效断言条数。 |

三个率与证据完整度**同分母**（全部逻辑点），分子依次扩大，因此必然有 `有效断言率 ≤ 断言覆盖率 ≤ 证据完整度`；这条不成立就说明统计有误。

#### 3.4.2 问题类型（见 1.2 问题分布表）

| 类型 | 一句话 | 定义 | 计数单位 | 基础严重度 |
|---|---|---|---|---|
| 场景覆盖不足 | 该测的场景没被断言覆盖到 | 逻辑点没有被任何用例断言 | 逻辑点 | 严重 |
| 断言质量低 | 测了，但断言没读到分支的产出 | 用例的断言没有读到它所覆盖逻辑点的任何决定性产出项；完全没有断言也算在内。只统计触达了本次逻辑点的用例 | 用例 | 高 |
| 测试对象偏移 | 跑的不是被测代码的真实实现 | 用例执行的是假实现，或由假实现代替真实实现给出结果 | 逻辑点 | 高 |
| 测试退化 | 显式删掉或放宽了已有用例 | 本次变更删除了、禁用了或放宽了已有的用例或断言行，导致它所守护的分支（含既有分支）失去断言保护 | 信号条 | 严重 |

容易混的两对：

- **场景覆盖不足与断言质量低**：前者的分支没有用例跑到，后者的分支跑到了但断言没读到它的产出；一个补用例，一个补断言。
- **场景覆盖不足与测试对象偏移**：前者是没人跑，后者是跑了假实现。

同一处证据只归一个根因类型；同一事实若同时落在两个计量单位上，按单位各记一次，但因为单位不同，各类数量不可相加。

#### 3.4.4 状态六档（见 3.3 矩阵「状态」列）

| 状态 | 定义 | 计入断言覆盖率 | 计入有效断言率 |
|---|---|---|---|
| 无测试 | 没有任何用例执行到该分支 | 否 | 否 |
| 已断言 | 有断言读到这条分支的决定性产出项（有效档） | 是 | 是 |
| 断言偏弱 | 有断言读到产出，但只落在非决定性量上 | 是 | 否 |
| 实现被替换 | 真实实现被探针、桩或 Mock 替换，且覆盖它的用例**全部**走假实现（零覆盖不算，落「无测试」） | 否 | 否 |
| 未断言 | 执行到了，但没有任何断言读到这条分支的产出项 | 否 | 否 |
| 无法判定 | 所需的证据不在手上，或结构不可解析 | 否 | 否 |

断言档位按**产出对账**判：只看分支代码列出它的产出项、标出决定性，再看断言读到哪一项，读到决定性项即有效。一条分支的产出读到任一项就算覆盖，不要求每项都被断言。

「无法判定」的判定口径有三类：结论依赖本次拿不到的证据（本 MR 没改、diff 里也没有，本地仓也读不到的既有测试、调用方、接口契约）；依赖没有验证过的运行前提（测试会话是否初始化、旧 JAR 是否在类路径、环境变量、执行顺序）；结构不可解析或触达无法确认。**三者都必须足以改变本逻辑点的结论**；只是「读不全」但结论不受影响时，照常判档。

不计入断言覆盖率的逻辑点 = 实现被替换 + 无测试 + 未断言 + 无法判定。四者都不在分子里；其中「无法判定」仍留在分母，只有「实现被替换」算进实现被替换率。

三个率的分母都是**全部逻辑点**，因此「无法判定」在所有率里都算作没覆盖、没拦住——它既不在分子里，也不会被移出分母。读不到多少由证据完整度单独说明，并必然有：`有效断言率 ≤ 断言覆盖率 ≤ 证据完整度`。

#### 3.4.5 严重度（见 1.2 问题分布表「严重度」列）

| 取值 | 含义 |
|---|---|
| 严重 | 基本没有证据，或证据被削弱、删除；修法是重做 |
| 高 | 证据存在，但没落到分支的产出上；修法是补 |

只有两档。基础严重度为「高」的类型在满足下列条件时升到「严重」，升级理由写在分布表的「升级理由」列：

- **断言质量低**：命中 ≥3 个用例，且占新增 + 修改用例 ≥50%
- **测试对象偏移**：被替换逻辑点 ≥3 个，且实现被替换率 ≥15%

场景覆盖不足与测试退化基础就是严重，不设升级；某类命中 0 条时不升级。

#### 3.4.7 最终结果定性规则（见 1.2 第一行）

> 本表是阈值的读者说明；判定规则调整时本表同步更新。

| 取值 | 含义 |
|---|---|
| 证据不足（前置） | 全部变更单元都是「无法获取」时直接给这一档，不产出质量结论 |
| 优秀 | 有效断言率 ≥75%、**全部**逻辑点 ≥8 个、且**计入的**测试退化 = 0 |
| 合格 | 未触发待改进与证据不足条件，也未达到优秀；零逻辑点的改动同样记合格 |
| 待改进 | 没带测试且看不清覆盖，或有效断言率 <50%，或有超过 2 条**计入的**测试退化 |
| 证据不足 | 带了测试，但证据完整度 <60%，可见样本不足以定性 |

判定按优先级：先看前置，再看证据是否足够，最后区分待改进、优秀与合格。
