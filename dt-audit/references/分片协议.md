# 分片协议

只有超过 [SKILL](../SKILL.md) 的阈值才用：**枚举片**按生产改动行切（> 800 行），**裁定片**按逻辑点数切（> 50 点）。一片不跨仓——跨仓的片读不到对方的调用关系，判不出可达性。

子代理不嵌套：片内不再开子代理。

## 通用约束

- 片内只读自己那份 diff 与测试文件，不读片外文件、不猜片外关系。
- 不跑脚本、不写 `evidence.md`、不编号。
- 输出是 JSON，字段名与本文一致；多写字段会被忽略，少写必填字段该片退回。

## 枚举片

**输入**：片内生产文件 diff、片内测试文件 diff、片编号。

**输出**：

```json
{
  "files": ["src/main/java/demo/OrderService.java"],
  "points": [
    {
      "位置": "src/main/java/demo/OrderService.java:42",
      "条件摘要": "if (order.amount > 100)",
      "来源": "新增",
      "触达候选": ["OrderServiceTest#appliesDiscount"]
    }
  ],
  "cases": [
    {
      "用例": "OrderServiceTest#appliesDiscount",
      "位置": "OrderServiceTest.java:20",
      "变更类型": "新增"
    }
  ]
}
```

- `位置` 必须形如 `路径:行号`；同一行上的两个分支（如 `catch (A | B e)`）保留成两条。
- `来源` 只填 新增 / 修改；来源为修改时把增删的子句写进 `条件摘要` 的括号里。
- `触达候选` 只写片内能确认的用例名；跨片或没有的给空数组，由主流程补。
- **不写** `编号`、`问题`、`原因`、`说明`。

**提示词要点**：只做盘点，不判定；判不出结构的片段入一条「不可解析」点（条件摘要写原因）；不读片外文件。

## 主流程收口

1. **校验**：JSON 可解析、必填字段非空、位置格式正确、`files` 覆盖本片生产文件。不合格退回该片一次；仍不合格，主流程自己读这一片（上限 ≤ 600 行），并在「取数备忘」记片号与原因。
2. **去重**：按「位置 + 条件摘要」合并，与逻辑点身份一致；「修改」来源内联在条件摘要里的括号注记不参与身份比较。
3. **编号**：合并后一次性分配，见 [逻辑点规则](逻辑点规则.md) 的「编号规则」。
4. **填覆盖用例**：用 `cases` 里的位置把 `触达候选` 写成 `用例名(文件:行号)`；找不到位置的只写名字，交步骤 3 修。同一身份出现在多片时，`触达候选` 取并集。
5. **补触达**：`触达候选` 为空的点，按生产符号做一次全局测试检索（`git grep <符号> <末提交> -- '*Test*'`），区分「真的没有用例」与「用例在片外」。
6. **打包裁定**：每批 50 点，带上覆盖用例与断言原文，末批可少于 50 点。

脚本：`assemble --mode merge` 完成 2–4 步。它**按本次传入的片重建点表，并保留证据表里已有的点**；枚举片里的 `问题 / 原因 / 说明` 会被忽略——判定只能由裁定片写。

## 裁定片

**输入**：50 个逻辑点（编号、位置、条件摘要、覆盖用例），以及覆盖用例的断言原文。

**输出**：

```json
{
  "points": [
    {
      "编号": "ORD-01",
      "覆盖用例": "OrderServiceTest#appliesDiscount(OrderServiceTest.java:30)",
      "问题": "有效",
      "原因": "",
      "说明": "assertEquals 核对到返回金额"
    }
  ]
}
```

- `问题` 只填 有效 / 未覆盖 / 无效 / 低价值 / 不确定。
- `原因` 必须属于该分类的枚举，见 [问题分类与判定](问题分类.md)；**有效留空**。
- 方向原因（原有用例不再执行 / 断言被注释 / 断言被弱化）的 `说明` 必须写明被改动的 `文件:行号`。
- 未覆盖的点 `覆盖用例` 留空；**不确定**可以留空（判不出可达、结构不可解析）；其余分类必须给出。
- 判不清就记「不确定」，不要按最坏猜。

**提示词要点**：只判本批，不枚举、不读生产 diff、不跨批；判格四态（核对到 / 只到形态 / 未核对 / 判不清），点取最好。

## 校验与写回

`assemble --mode judge` 负责写回，`stats` 负责最终校验：

- 问题 ∈ 五类；原因 ∈ 对应分类的枚举
- 有效的原因必须为空；未覆盖的覆盖用例必须为空；不确定可留空
- 覆盖用例里的用例名必须在用例清单里
- 方向原因的说明必须带行号
- 五类计数之和等于逻辑点总数

不合格就修，不要绕过脚本手拼表格。

## 调度

什么时候派、一次派几片、用 `subagent` 逐个派还是用 `workflow` 扇出，由运行的 agent 自行决定。本节只约束切片标准与输入输出，不约束并发。

分片只降峰值，不降总量：低于阈值不要切。
