# 范围规则

步骤 1 使用。目标是让**每个变更文件**都有分类结论，且排除项可解释、可复核。

## 判定顺序

按下列顺序逐个文件判，**命中即停**。顺序本身就是优先级，用来消除一个文件同时像好几类的歧义（如 `setup.py` 既是 `.py` 又是构建文件）。

| 序 | 分类 | 判据 | 处理 |
|---|---|---|---|
| 1 | 二进制 / 子模块 | 二进制标志或子模块标志为真 | 排除 |
| 2 | 生成代码 | 见「生成代码识别」 | 排除 |
| 3 | 构建文件 | 文件名为 `CMakeLists.txt`、`Makefile`、`pom.xml`、`build.gradle*`、`setup.py`、`pyproject.toml`、`meson.build` | 排除 |
| 4 | 白名单外 | 扩展名不在语言白名单里，按下列细类记 | 排除 |
| 5 | 测试代码 | 见「测试文件识别」 | 进测试证据池 |
| 6 | 生产代码 | 白名单扩展名且非测试 | 进文件统计（C / C++ 只计文件数，不进逻辑点分母） |
| 7 | 其余 | 以上都不命中 | 排除并注明原因 |

第 4 类的细类是：**配置 / 资源**（`.yaml` `.yml` `.json` `.xml` `.properties` `.ini` `.conf` `.toml` `.env` 等）、**文档**（`.md` `.txt` `.adoc` `.rst` 等）、**脚本**（`.sh` `.bat` `.ps1` `.cmd`）、**其他语言**（不在白名单）。

**排除项的分类键唯一**：因为命中即停，一个文件只会落一个分类，证据表「变更概览」里的 `排除：<分类>` 不会重复。

## 语言白名单

只审计以下扩展名：

| 语言 | 扩展名 |
|---|---|
| Java | `.java` |
| Python | `.py` |
| C | `.c`、`.h` |
| C++ | `.cc`、`.cpp`、`.cxx`、`.hpp`、`.hh`、`.hxx` |

`.h` 归 C 还是 C++，看同目录实现的源码语言；判不出时按 C++ 处理并标注。头文件与内联模板里的逻辑点**计入生产代码**。

`.py` 也走上面的判定顺序：命中构建文件名就排除（如 `setup.py`），否则再看是否测试，最后才按生产代码处理；都不命中才排除（运维脚本、一次性脚本不属于审计范围）。

## 测试文件识别

路径约定与内容特征**两条判据取或**：命中任一即视为测试文件。一个文件被判为测试后**不再计入生产分母**，不做双重归属。

路径约定：

- Java：`src/test/`、`src/it/`、`*Test.java`、`*Tests.java`、`*IT.java`、`*Spec.java`
- Python：`tests/`、`test/`、`test_*.py`、`*_test.py`、`conftest.py`
- C / C++：`test/`、`tests/`、`unittest/`、`*_test.c`、`*_test.cpp`、`*Test.cpp`、`*_unittest.cc`

内容特征：

- Java：`@Test`、`@ParameterizedTest`、`@TestFactory`、`extends TestCase`
- Python：`def test_`、`class Test`、`import pytest`、`import unittest`、`@pytest.mark`
- C / C++：引用 CMocka / Unity / GoogleTest / Catch2 / doctest / Boost.Test / CppUTest / CppUnit 的头文件，或出现对应测试宏

## 生成代码识别

命中任一即排除：

- 文件头含 `@Generated`、`DO NOT EDIT`、`Code generated by`、`此文件由…自动生成`
- 路径含 `/generated/`、`/gen/`、`/build/`、`/target/`、`/out/`
- 文件名模式：`*.pb.h`、`*.pb.cc`、`*_generated.*`、`*Mapper.xml`、`*.g.cs`

Lombok 一类注解处理器不落盘生成文件，不涉及本规则。改动的生成文件若文件头不在 diff 范围内、只靠路径也判不出，按「判不准一律排除」处理，并在「取数备忘」注明「N 个文件判不准已排除」。

## 输出

**纳入的文件**逐个进证据表「范围」段，一行一个，含路径、分类、**语言**（Java / Python / C / C++）、来源档位、新增、删除。

**排除的文件**只在证据表「变更概览」里按分类汇总数量（如 `排除：配置 → 8`），不逐个列路径、也不逐个写理由：排除项只用来知道有多少东西没进审计范围，不参与任何判定。

报告 3.2 的构成表由「变更概览」的排除项与「范围」段的纳入文件聚合得出，不新增数据源。
