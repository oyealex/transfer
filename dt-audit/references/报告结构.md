# 报告结构

步骤 5 使用。

章节骨架与表头以 [报告模板](报告模板.md) 为准；本文说明字段含义与填写规则。骨架归模板、规则归本文，两者不互相仲裁。

报告分三大章：整体结论、DT 质量评估、附录。

默认写入工作目录下的 `.dt-audit/<对象>/DT-AUDIT-REPORT.md`；用户指定路径时以用户为准。对话里只贴结论区和文件路径，不重复粘贴全文。

## 一、结论不是单一短语

整体结论陈列**命中的问题类型和命中数量**，不给合成结论、不给总分。问题类型固定为 4 类，见 [问题类型](问题类型.md)；证据不足单列在分布表之外。

这样做的原因：多个问题会同时存在（比如断言精确但实现被替换、同时分支大量未观测），压成一个短语必然丢掉信息；分布表既能一眼看出主症，也不丢信息。

## 二、指标定义

| 指标 | 公式 | 用途 |
|---|---|---|
| 变更生产代码量（KLOC） | 生产代码的新增侧行数（additions，含修改行）÷ 1000，不含删除与测试行 | 必报 |
| 新增 DT 数 | 本对象新增的测试方法数 | 必报 |
| 新增 DT 密度 | 新增 DT 数 ÷ 变更生产代码 KLOC；KLOC 为 0 时写「不适用」 | 必报，仅陈述 |
| 可判定决策点数 | 排除「无法判定」后的决策点数，只在 Java / Python 上枚举 | 观测率与架空率的分母 |
| 观测率 | （已观测 + 部分观测）÷ 可判定决策点数 | 覆盖口径 |
| 可拦截率 | 已观测 ÷ **全部决策点数** | 拦截口径，主指标 |
| 判别性断言占比 | 判别性断言条数 ÷ 冻结范围内的断言条数；一条断言只计一次，档位取它在所绑定决策点上的最高档 | 问题分布与维度总评 |
| 架空率 | 实现被替换的决策点数 ÷ 可判定决策点数 | 问题分布与维度总评 |
| 证据完整度 | 可判定决策点数 ÷ 全部决策点数 | 置信度 |

**两个率的分工**：观测率是**覆盖口径**——只要有一条断言在看就计入，部分观测也算；可拦截率是**拦截口径**——只算「已观测」（断言能把错误变红），分母用全部决策点，把「部分观测」（拦不住）和「无法判定」（不知道）都算作没拦住。两者并列呈现，不做合成，也不互相替代：前者说明覆盖到哪，后者说明真能拦住多少。

决策点只在 Java / Python 上枚举。C / C++ 不枚举决策点，只给文件级结论，不进任何分母，报告标注「受限检测」；受限数量按**文件数**统计。场景覆盖不足与测试对象偏移的分子也只统计 Java / Python 决策点。

**判定水位**（数值只在这里出现一次）：

- 证据完整度下限 **0.60**，低于它按「证据不足」提示；三档为 ≥**0.90**「完整」、≥**0.60**「部分」、其余「不足」。
- 维度「一句话总评」的良好水位：观测率 **0.70**、判别性断言占比 **0.70**。高于良好水位为高，低于覆盖低水位 **0.40** 为低，其余为中。可拦截率只陈述数值，不设水位。
- 新增 DT 密度参考带 **5–30** 个/KLOC，仅用于措辞，不参与判定。

**断言统计范围（唯一口径）**：只统计本对象新增或修改的用例内的断言；既有用例只作触达证据，其断言不进分母；同一行内多条按条计。不冻结就不可比：同一套用例在三次运行里分别被数成 89、77、111 条断言，判别性从 74.2% 漂到 80.5% 再漂到 85.6%，看起来像质量在变，其实只是分母在变。问题类型、测试框架识别与报告 2.1 一律引用本节，不另写。

观测率把「部分观测」算作已覆盖，因为它至少有一条断言在看。**没有被观测到的决策点 = 无测试 + 实现被替换 + 未观测**，三者之和应当等于可判定决策点数减去已观测与部分观测，报告里要能对上。

## 四、各章规则

### 1.1 基本信息

按对象类型二选一，不混用：

- **SR / AR**：编号、变更的生产代码（KLOC）、新增 DT 数、新增 DT 密度（个/KLOC）、涉及代码仓、证据来源分布，另附**关联 MR 清单**（地址、标题、作者）。
- **MR**：地址、标题、作者、涉及代码仓、变更的生产代码（KLOC）、新增 DT 数、新增 DT 密度（个/KLOC）、证据来源分布。

「变更的生产代码」只算生产代码的新增侧行数（含修改），不含删除与测试行。证据来源按**单元数**统计：本地 / 平台 / 无法获取。

### 1.2 结论

第一行给 **DT 质量定性**，按下面顺序判定，命中即停：

| 步 | 条件 | 结论 |
|---|---|---|
| R0 | 全部决策点 = 0 | 合格 |
| R1 | 新增 + 修改用例 = 0 且 证据完整度 < 60% | 待改进 |
| R2 | 证据完整度 < 60% | 证据不足 |
| R3 | 可拦截率 < 50% 或 判别性断言占比 < 50% 或 测试退化 > 2 条 | 待改进 |
| R4 | 可拦截率 ≥ 75% 且 判别性断言占比 ≥ 75% 且 全部决策点 ≥ 8 且 测试退化 = 0 | 优秀 |
| R5 | 其余 | 合格 |

定性的三个取向：

- **优秀要少**：四个条件同时满足才给，任一条差一点就落合格。
- **待改进看可见的问题**：R1 把「没带测试又看不清覆盖」算成待改进而不是证据不足——提交代码该带用例，看不清是提交方的责任。
- **证据不足只做兜底**：只有带了测试、却确实读不到足够内容时才用，不拿它当「不想判」的出口。

R4 里不再单列「证据完整度」条件：可拦截率的分母是全部决策点，可拦截率 ≥ 75% 已经蕴含完整度 ≥ 75%。

「测试退化」只统计证据表信号段里「计入 = 是」的条数——即三段证据齐全、确实让本次变更的分支失去防护的那些。1–2 条不足以判待改进，但会挡住优秀。

依据写一行，说清命中哪条规则、卡在哪个条件，取自 `stats.json` 的「定性」，不重新推导。

其后四块内容按顺序：问题分布表、证据不足提示、四个率、一句话判断。

占比的分母按单位取：决策点类用可判定决策点数，用例类用测试用例总数；信号条不填占比，写「—」。

分布表覆盖 4 类（场景覆盖不足、断言质量低、测试对象偏移、测试退化）；证据不足单列在提示行，不进分布表，也不计入「其余 N 类未命中」。表下写「其余 N 类未命中」，N = 4 − 命中类数。

四个率一行陈列，不做合成、不排序、不加权：观测率、可拦截率、判别性断言占比、架空率。

**零决策点与零可判定的处理（唯一口径）**：

- 决策点总数为 0：定性写「合格」；问题分布留空，写「本次改动未引入行为分支」；证据不足提示写「证据完整度：不适用（无决策点）」；四个率写「不适用」；2.2 / 2.3 总评写「无行为分支，不评估」；跳过步骤 4，原因记入 3.1。
- 决策点总数大于 0 但可判定为 0：保留 3.3 矩阵，不写「未引入行为分支」；四个率写「不适用」；2.2 / 2.3 总评写「全部无法判定，不评估」。

### 1.3 主要缺口（Top 3）

按影响档降序取 3 条，每条一行：位置 + 问题 + 影响档 + 建议动作。影响档判据见「影响排序」。

### 2.x 维度章节

三个维度用同一个三段式：

1. **一句话总评**，不超过 40 字，说清整体水平和一个最突出的问题。水平按 §二 的判定水位判断：高于良好水位为高，低于覆盖低水位为低，其余为中；不写分数。
2. **问题清单**，严重程度由高到低。每条含：文件行号、现象、证据原文、后果、问题类型与子类。
3. **本维度补测建议**，2 到 3 条，带落点。

| 维度 | 必含内容 | 覆盖的问题类型 |
|---|---|---|
| 2.1 DT 断言质量 | 断言总数与判别性占比、无断言用例、只用交互验证的用例、测试退化（计入条数与提示条数分开）、判别力抽检结果 | 断言质量低、测试退化 |
| 2.2 Mock 质量 | Mock 情形分布（提示信息）、架空率、被替换决策点清单、契约漂移 | 测试对象偏移 |
| 2.3 分支覆盖 | 观测率、可拦截率、未覆盖清单（只列无测试与分支未观测，按影响档排序，实现被替换交叉引用 2.2）、异常路径与边界细分；测试脱靶命中时另起一行 | 场景覆盖不足 |

**去重规则**：同一个问题只在根因所在的维度展开，其他维度用决策点编号交叉引用，不复述。例如探针替换导致 9 个决策点无观测，根因在 2.2，2.3 只列编号并注明「见 2.2」。

### 影响排序（只用于排序，不计入任何数字）

1.3 的 Top 3 与 2.3 的未覆盖清单按**影响档**降序排列。影响档看这条分支控制什么，不看问题类型：

| 影响档 | 判据 |
|---|---|
| 高 | 安全 / 权限 / 鉴权、金额 / 计费 / 配额、数据写入或删除、状态迁移、对外契约（返回结构、错误码） |
| 中 | 业务计算、数据转换、字段默认值、缓存与降级 |
| 低 | 日志、文案、埋点、调试开关、纯展示 |

只在列进这两处的条目上判一次，不写进证据表，不参与任何计数。

### 3.1 分析范围与证据来源

限制说明必须包含两条：**未运行测试，用例当前是否通过未知**；**结论只覆盖实现自证能力**。

### 3.4 枚举释义

3.4 的固定内容在 [3.4 枚举释义](3.4-枚举释义.md)，报告里整段注入，不改写、不合并、不精简。
