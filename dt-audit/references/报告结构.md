# 报告结构

步骤 5 使用。

章节骨架与表头以 [报告模板](报告模板.md) 为准；本文说明字段含义与填写规则。

报告分三大章：整体结论、DT 质量评估、附录。

默认写入工作目录下的 `.dt-audit/<对象>/DT-AUDIT-REPORT.md`；用户指定路径时以用户为准。对话里只贴结论区和文件路径，不重复粘贴全文。

## 一、结论不是单一短语

整体结论陈列**命中的问题类型和命中数量**，不给合成结论、不给总分。问题类型固定为 11 类，见 [问题类型](问题类型.md)。

这样做的原因：多个问题会同时存在（比如断言精确但实现被替换、同时分支大量未观测），压成一个短语必然丢掉信息；分布表既能一眼看出主症，也不丢信息。

## 二、指标定义

| 指标 | 公式 | 用途 |
|---|---|---|
| 变更生产代码量（千行） | 生产代码的新增侧行数（additions，含修改行）÷ 1000，不含删除与测试行 | 必报 |
| 新增 DT 数 | 本对象新增的测试方法数 | 必报 |
| 新增 DT 密度 | 新增 DT 数 ÷ 变更生产代码千行；千行为 0 时写「不适用」 | 必报，仅陈述 |
| 可判定决策点数 | 排除「无法判定」与「归属存疑」后的决策点数，仅 Java / Python | 各比率的分母 |
| 观测率 | （已观测 + 部分观测）÷ 可判定决策点数，分母只含 Java / Python | 问题分布与维度总评 |
| 判别性断言占比 | 判别性断言条数 ÷ 冻结范围内的断言条数（口径见 [测试框架识别](测试框架识别.md)）；一条断言只计一次，档位取它在所绑定决策点上的最高档 | 问题分布与维度总评 |
| 架空率 | 实现被替换的决策点数 ÷ 可判定决策点数，分母只含 Java / Python | 问题分布与维度总评 |
| 证据完整度 | 可判定单元 ÷ 全部候选单元 | 置信度 |

可判定单元的取值：Java / Python 用决策点；C / C++ 用「文件 + 测试目标」组合。C/C++ 的决策点不进观测率与架空率的分母，只在附录矩阵里列状态，报告标注「受限检测」。A1 / D1 / C1 的分子也只统计 Java / Python 决策点；C/C++ 单列，不并入问题分布的数量。

观测率把「部分观测」算作已覆盖，因为它至少有一条断言在看。**没有被观测到的决策点 = 无测试 + 实现被替换 + 未观测**，三者之和应当等于可判定决策点数减去已观测与部分观测，报告里要能对上。

## 三、章节结构

```
# DT 质量审计报告 — <检测对象>

## 一、整体结论
### 1.1 检测对象
### 1.2 结论
### 1.3 DT 与代码数据
### 1.4 主要缺口（Top 3）

## 二、DT 质量评估
### 2.1 DT 断言质量
### 2.2 Mock 质量
### 2.3 分支覆盖

## 三、附录
### 3.1 分析范围与证据来源
### 3.2 变更构成与排除清单
### 3.3 决策点与观测矩阵
### 3.4 枚举释义
```

报告顶部可加一行「与默认口径的偏差声明」，只在检测对象不是 SR、或跳过了某一步时使用。

## 四、各章字段

### 1.1 检测对象

对象类型（SR / MR 批次 / 提交批次 / 混合批次）、归一化标识与原始输入、时间、MR 数或提交数、涉及仓数、关联能力（索引级 / 静态级 / 文件级）、证据来源分布。

### 1.2 结论

分三块，按顺序：

**（1）问题分布表**

只列命中的类型。排序规则：严重度降序；同严重度按计数单位优先级（决策点 > 用例 > 对象 > 断言条 > 信号条 > 处），再按数量降序。单位逐行标注，不给合计。

| 编号 | 类型 | 具体表现 | 数量 | 占同类总数 | 严重度 |
|---|---|---|---|---|---|
| C1 | 实现被替换 | 7 个取数方法与 2 个静态入口被探针替换 | 9 个决策点 | 15.8% | 严重 |
| D1 | 分支未观测 | 空列表、库存不足、重定向降级等分支无用例执行 | 17 个决策点 | 29.8% | 中 |
| B2 | 断言不判别 | 以「非空」「非零」为主，未校验具体值 | 23 条断言 | 25.8% | 中 |

占比的分母按单位取：决策点类用可判定决策点数，用例类用测试用例总数，断言类用断言总数；对象类、信号条与「处」不填占比，写「—」。

分布表覆盖 10 类（A1–A3、B1–B3、C1–C3、D1）；A4 单列在证据不足行。表下写「其余 N 类未命中」，N = 10 − 命中类数。

**（2）证据不足提示**

单独一行，不与质量问题混排：

```
证据不足：0 个决策点不可判定 ｜ 证据完整度 100%（完整）
```

A4 不进问题分布表，只在证据不足行报告，因此不计入「其余 N 类未命中」。

决策点总数为 0 时：问题分布留空，写「本次改动未引入行为分支」；1.2（2）写「证据完整度：不适用（无候选单元）」；1.3 的观测率、判别性断言、架空率写「不适用」；2.2 / 2.3 总评写「无行为分支，不评估」；跳过步骤 4 与双轮，原因记入 3.1。

决策点总数大于 0 但可判定为 0 时：保留 3.3 矩阵，不写「未引入行为分支」；1.3 的率写「不适用」，2.2 / 2.3 写「全部无法判定，不评估」。

**（3）一句话判断**

不超过 50 字，从分布里生成，点出数量最大或严重度最高的两类问题及其后果。不是固定枚举，允许自由表述。证据完整度低于下限时删去本块，只保留（1）（2）。

### 1.3 DT 与代码数据

```
变更生产代码 0.788 千行 ｜ 新增 DT 38 个 ｜ 新增 DT 密度 48.2 个/千行
观测率 54.4% ｜ 判别性断言 74.2% ｜ 架空率 15.8%
```

### 1.4 主要缺口

Top 3，按影响半径排序。每条一行：位置 + 问题 + 建议动作。

### 2.x 维度章节

三个维度章节用同一个三段式：

1. **一句话总评**，不超过 40 字，说清这个维度的整体水平和一个最突出的问题。水平按配置的两个水位判断：高于良好水位为高，低于低水位为低，其余为中；不写分数
2. **问题清单**，严重程度由高到低。每条必须含：文件行号、现象、证据原文、后果、对应问题类型编号
3. **本维度补测建议**，2 到 3 条，带落点

| 维度 | 必含内容 | 覆盖的问题类型 |
|---|---|---|
| 2.1 DT 断言质量 | 断言总数（写清新增 / 修改多少个用例、共多少条）与判别性占比、无断言用例、只用交互验证的用例、证据被削弱、判别力抽检结果 | A3、B1、B2、B3 |
| 2.2 Mock 质量 | Mock 情形分类分布、架空率、被替换决策点清单、契约漂移风险 | C1、C2、C3 |
| 2.3 分支覆盖 | 观测率、未覆盖决策点清单（只列 A1 与 D1，C1 交叉引用 2.2）、异常路径与边界细分；A2 命中时另起一行写「A2 对象级：有测试变更但全部决策点无测试」 | A1、A2、D1 |

**去重规则**：同一个问题只在根因所在的维度展开，其他维度用决策点编号交叉引用，不复述。例如探针替换导致 9 个决策点无观测，根因在 2.2，2.3 只列编号并注明「见 2.2」。

### 3.1 分析范围与证据来源

范围表（MR 或提交、标题、作者、来源档位、纳入结论）、差分基准与自校验、证据完整度与限制、双轮裁定结果、不可判定清单、平台兜底清单、受限语言说明，以及固定声明。

限制里必须包含两条：**未运行测试，用例当前是否通过未知**；**结论只覆盖实现自证能力**。

### 3.2 变更构成与排除清单

分类统计表，加逐文件排除清单（路径、分类、纳入或排除、理由、来源档位）。

### 3.3 决策点与观测矩阵

口径说明在前，然后全表：编号、位置、类型、条件或分支、触达用例、状态。末尾分三行：全部决策点合计、其中可判定数、其中 C/C++ 受限数；六种状态分别计数。

### 3.4 枚举释义

逐条解释报告里作为标签出现的枚举：问题类型、决策点类型、观测状态、严重度、其余标签。

固定内容与表头以 [报告模板](报告模板.md) 的 3.4 为准，逐表照抄，不改写、不合并、不精简。

## 五、固定声明

报告的 3.1 节必须原样包含这句：

> 本结论只覆盖实现自证能力：代码自己引入的分支是否被自己的测试观测到。漏实现与设计缺陷不在检测范围内。

## 六、整体结论章示例

下面只是版式示例，内容不进报告；实际数据以被审计对象为准。

```
检测对象：SR-1234 ｜ 2026-11-16 ｜ MR 3 个 ｜ 仓 1 个 ｜ 关联能力 静态级

问题分布（命中 5 类 / 共 10 类）

| 编号 | 类型 | 具体表现 | 数量 | 占同类总数 | 严重度 |
| A1 | 无测试 | 空列表、库存不足、重定向降级等分支根本没有用例执行 | 17 个决策点 | 29.8% | 严重 |
| C1 | 实现被替换 | 7 个取数方法与 2 个静态入口被 @Override 探针替换 | 9 个决策点 | 15.8% | 严重 |
| B1 | 无断言用例 | PatchUpdateServiceTest 跳过场景 | 1 个用例 | 2.6% | 高 |
| B3 | 只用交互验证 | PatchUpdateServiceTest 状态刷新 | 1 个用例 | 2.6% | 高 |
| B2 | 断言不判别 | 只校验非空或集合大小，未校验具体值 | 23 条断言 | 25.8% | 中 |

其余 5 类未命中。

证据不足：0 个决策点不可判定 ｜ 证据完整度 100%（完整）

一句话判断：断言本身较精确，但真实取数被探针替换、17 个关键分支根本没有用例执行，
所以现有用例主要证明了比较符写对了，没证明取到的值对不对。
```
