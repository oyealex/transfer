# DT 问题类型

步骤 2、3、5 使用。

整体结论按这里列的 **4 类**统计命中数量；证据缺口作为提示单列在分布表之外。类型固定，口径统一。

每类只回答一个问题：**命中了多少**。不做加权、不做合成分数。

## 分类

四类对应 DT 拦不住问题的四种方式，也对应四种修法：

| 类型 | 一句话 | 定义 | 计数单位 | 基础严重度 |
|---|---|---|---|---|
| 场景覆盖不足 | 该测的场景没被断言覆盖到 | 逻辑点没有被任何用例断言 | 逻辑点 | 严重 |
| 断言质量低 | 测了，但断言没读到分支的产出 | 用例的断言没有读到它所覆盖逻辑点的任何决定性产出项；完全没有断言也算在内。只统计触达了本次逻辑点的用例 | 用例 | 高 |
| 测试对象偏移 | 跑的不是被测代码的真实实现 | 用例执行的是假实现，或假实现替真实实现作答 | 逻辑点 | 高 |
| 测试退化 | 显式删掉或放宽了已有用例 | 本次变更删除了、禁用了或放宽了已有的用例或断言行，且导致它所守护的分支（含既有分支）失去断言保护 | 信号条 | 严重 |

修法分别是：补用例、补断言、收窄 mock、恢复证据。

**四类的判定依据互斥，计量单位不同**：一处证据只归一个根因类型。同一个事实也可能同时落在两个计量单位上——比如「用例完全没有断言」既让逻辑点落「未断言」（场景覆盖不足），也让该用例落「无断言用例」（断言质量低）。这是两把尺子各说一次，用逻辑点编号交叉引用；因为单位不同，各类数量不可相加。

## 提示：证据缺口

| 提示 | 定义 | 计数单位 |
|---|---|---|
| 证据缺口 | 无法判定的逻辑点（含结论依赖未验证的运行前提、结构不可解析、触达无法确认） | 逻辑点 |

证据缺口是**置信度提示**，不是质量问题，不进分布表。它表示「看不清楚」，不等于没问题。

「无法获取」的 MR 是单元级的另一件事：它不进分母、不计数、也不记为零，只在 3.1 单列。它**不**折算成证据缺口的逻辑点数——那个 MR 根本没有产生逻辑点。

## 子类明细

子类只出现在报告 2.x 的问题条目里，不进分布表，不单独统计命中数。

| 类型 | 子类 | 判据 |
|---|---|---|
| 场景覆盖不足 | 无测试 | 没有任何用例执行到该逻辑点 |
| | 测试脱靶 | 有测试变更，但该对象的全部逻辑点都是无测试（对象级提示） |
| | 分支未断言 | 执行到了，但没有任何断言读到这条分支的产出项 |
| 断言质量低 | 无断言用例 | 用例方法体内没有任何断言调用 |
| | 断言未读到产出 | 断言只读到长度、类型、非空、裸异常这类非决定性量，没读到这条分支的决定性产出项（按条） |
| | 只用交互验证 | 断言只落在假实现的调用上，而被测分支的产出是本对象自己算出的值或状态（按用例） |
| 测试对象偏移 | 实现被替换 | 被替换的方法体内含本对象的逻辑点，覆盖它的用例全走假实现 |
| | 契约漂移 | 假实现的返回值与真实契约不一致（按处） |
| 测试退化 | 断言弱化 / 测试文件删除 / 新增禁用 / 断言被注释 / 用例方法体留空 / 测试输入弱化 | 见下节六条信号 |

## 严重度

只有两档：**严重**、**高**。基础严重度见分类表；满足下列条件时从高升到严重，报告里标注升级理由：

| 类型 | 升级条件 | 升级后 |
|---|---|---|
| 断言质量低 | 命中 **≥ 3 个用例**，且占新增 + 修改用例 **≥ 50%** | 严重 |
| 测试对象偏移 | 被替换逻辑点 **≥ 3 个** 且 实现被替换率 **≥ 15%** | 严重 |

升级只看命中的类型：某类命中 0 条时不升级，也不写升级理由。场景覆盖不足与测试退化基础就是严重，不设升级。

## 判定与来源口径

判定方法即分类表的定义，不另列。四条准入条件同时成立才允许记一条：

1. **位置可指**：说得出文件与行号，或说得出逻辑点编号。
2. **归属可绑**：能对上本次变更的一个逻辑点或一条用例。
3. **来源够用**：按 diff 的改动内容判，内容够就判。**来源档位不决定能不能判**——含本地仓与仅 diff 一样判；不够才落「无法判定」并计入证据缺口。
4. **产出可指**：说得清这条分支的决定性产出项是哪几项，并说明断言读到的不在其中。分支代码读得到、只是决定性判不准时，按已断言计、不记；分支代码读不到或触达无法确认时，落「无法判定」，不记问题。措辞里出现「可能」「也许」的，不记。

来源为「无法获取」的 MR 不进分母、不计数、也不记为零——把无法判断当成零风险，会让统计口径失真。

## 测试退化的六条信号

**只认显式改动**：本次变更里删除了、禁用了、或放宽了**已有的**用例或断言行。

新增生产代码但没有新增对应用例，**不算测试退化**，按「场景覆盖不足」的无测试 / 未断言计。这是两类不同的事：一类是从没测过，一类是原本测过、这次被拿掉了。

### 和场景覆盖不足的分界

看**基线有没有防护**，不看现在有没有。这张表判的是「要不要记一条测试退化信号」，逻辑点本身的状态照旧按现在有没有断言记：

| 情形 | 基线 | 现在 | 怎么记 |
|---|---|---|---|
| 新增的生产代码，没有对应用例 | 没有这条分支 | 未断言 | 逻辑点记无测试；**不记退化** |
| 本次修改的分支，测试没动也没补 | 有有效断言 | 未断言 / 断言偏弱 | 逻辑点按现状记；**不记退化** |
| 已有或本次修改的分支，测试被删 / 禁用 | 有有效断言 | 未断言 | 逻辑点记无测试，**并记 1 条退化** |
| 已有分支，断言被弱化 | 有有效断言 | 断言偏弱 / 未断言 | 逻辑点按现状记，**并记 1 条退化** |
| 已有分支，本来就一直没测 | 无测试 | 无测试 | 逻辑点记无测试；**不记退化** |

一句话：**测试退化只回答「基线有防护、现在没了或弱了」**；逻辑点「现在有没有防护」由状态回答。两者单位不同，同一处改动会在两处各留一条记录，报告用逻辑点编号交叉引用，不算重复计数。

一条信号要**计入**，必须三段同时成立：

1. **指得出具体改动**：哪个测试文件、哪条用例、哪个断言行
2. **证得出它原本在守本次的改动**：这条测试的断言引用了本次变更的生产符号，能对应到某个逻辑点
3. **证得出守不住了**：改动之后，该逻辑点的断言消失或变弱

缺任何一段，只作**提示**（信号表里「计入」填「否」），不进分布、不进定性。

| # | 信号 | 判定方法 |
|---|---|---|
| 1 | 断言弱化 | 同一断言行被修改：旧侧精确、新侧宽泛（`assertEquals` → `assertNotNull` / `assertTrue`；具体异常 → `Exception` / `Throwable`）。**不按断言行数减少判**——重构、抽公共方法、参数化都会让行数减少 |
| 2 | 测试文件删除 | 测试文件被删，且本次没有新增任何测试文件。排除重命名 / 搬移 |
| 3 | 新增禁用 | 新增**代码行**出现 `@Disabled`、`@Ignore`、`@pytest.mark.skip`、`@pytest.mark.skipif`、`GTEST_SKIP`、`TEST_IGNORE`、Catch2 `SKIP(`、CMocka 跳过写法。**不认裸 `skip` / `xit`**——会命中变量名、字符串和注释，`xit` 也不在 Java / Python 范围 |
| 4 | 断言被注释 | 删除侧有有效断言，新增侧把**同一段断言文本**注释掉了。新写一行注释提到断言不算 |
| 5 | 用例方法体留空 | `@Test` 注解还在、方法体从有内容变为空或只剩跳过。排除搬到父类 / 工具类、改成参数化包装 |
| 6 | 测试输入弱化 | **通常只作提示**：它多半指不出「被删的行」，不满足第 1 段。只有能具体指出被削弱的输入、被削弱的断言与被损的逻辑点时，才按三段计入 |

C / C++ 没有逻辑点，其信号只能作提示：计入条数为 0。

**去重**：同一位置同一信号只记 1 条。位置通常写成「文件:行号」，因此同一文件的不同位置各算一条。

## 计数规则

1. **断言质量低按用例计**：一个用例内有多条没读到产出的断言也只算 1 个用例；这些断言的条数在明细里单独报。
2. **测试脱靶是对象级提示**：命中时只作「场景覆盖不足」的附注，不并入逻辑点数。
3. **测试对象偏移与场景覆盖不足不重叠**：实现被替换的逻辑点记测试对象偏移，不记「分支未断言」。
4. **一处证据只归一个根因类型**：同一条信号同时支撑多个类型时，按根因归属计一次。
5. **单位不可混加**：逻辑点、用例、信号条是不同单位，分布表逐行标注，不要给合计。
6. **子类不进分布表**：子类只在 2.x 的问题条目里出现。
