# DT 问题类型

步骤 2、3、5 使用。

整体结论按这里列的 **4 类**统计命中数量；证据不足作为提示单列在分布表之外。类型固定，口径统一。

每类只回答一个问题：**命中了多少**。不做加权、不做合成分数。

## 分类

四类对应 DT 拦不住问题的四种方式，也对应四种修法：

| 类型 | 一句话 | 定义 | 计数单位 | 基础严重度 |
|---|---|---|---|---|
| 场景覆盖不足 | 该测的场景没被观测到 | 决策点没有被任何用例观测 | 决策点 | 严重 |
| 断言质量低 | 测了，但断言看不出对错 | 用例有断言，却没有一条能区分对错 | 用例 | 高 |
| 测试对象偏移 | 跑的不是被测对象的真实实现 | 用例执行的是假实现，或假实现替真实实现作答 | 决策点 | 高 |
| 测试退化 | 显式删掉或改松了已有用例 | 本次变更删除了、禁用了或改松了已有的用例或断言行，且导致本次变更的分支失去观测 | 信号条 | 严重 |

修法分别是：补用例、补断言、收窄 mock、恢复证据。四者互不重叠。

容易混的两对：

- **场景覆盖不足与断言质量低**：前者的分支根本没有用例观测到；后者的分支观测到了，只是断言分不出对错。一个要补用例，一个要补断言。
- **场景覆盖不足与测试对象偏移**：前者是没人跑，后者是跑了假实现。

## 提示：证据不足

| 类型 | 定义 | 计数单位 |
|---|---|---|
| 证据不足 | 无法判定（含结论依赖未验证的运行前提），或来源不可获取 | 决策点 |

证据不足是**置信度提示**，不是质量问题，不进分布表。它表示"看不清楚"，不等于没问题。

## 子类明细

子类只出现在报告 2.x 的问题条目里，不进分布表，不单独统计命中数。

| 类型 | 子类 | 判据 |
|---|---|---|
| 场景覆盖不足 | 无测试 | 没有任何用例执行到该决策点 |
| | 测试脱靶 | 有测试变更，但该对象的全部决策点都是无测试（对象级提示） |
| | 分支未观测 | 执行到了，但没有任何断言观察 |
| 断言质量低 | 无断言用例 | 用例方法体内没有任何断言调用 |
| | 断言不判别 | 断言只证明跑通了或只校验形状，不能区分对错（按条） |
| | 只用交互验证 | 断言只落在假实现的调用上，没有被测对象的结果断言 |
| 测试对象偏移 | 实现被替换 | 被替换的方法体内含本对象的决策点，覆盖它的用例全走假实现 |
| | 契约漂移 | 假实现的返回值与真实契约不一致（按处） |
| 测试退化 | 断言弱化、测试删除、新增禁用、断言被注释、测例留空体、测试输入弱化 | 见下节六条信号 |

## 严重度升级

基础严重度按上表；满足下列条件时上调一档，报告里标注升级理由：

| 类型 | 升级条件 | 升级后 |
|---|---|---|
| 断言质量低 | 判别性断言占比 **<50%** | 严重 |
| 测试对象偏移 | 被替换决策点 **≥3 个** 且 架空率 **≥15%** | 严重 |

场景覆盖不足与测试退化基础就是严重，不设升级。

## 命中判定与准入

判定方法即上表的定义，不另列。**来源档位不决定能不能判**——本地与平台都按改动内容判，内容够就判，不够才落「无法判定」并计入证据不足。来源为「无法获取」的 MR 不进分母、不计数、也不记为零——把无法判断当成零风险，会让统计口径失真。

## 测试退化的六条信号

**只认显式改动**：本次变更里删除了、禁用了、或改松了**已有的**用例或断言行。

新增生产代码但没有新增对应用例，**不算测试退化**，按「场景覆盖不足」的无测试 / 未观测计。这是两类不同的事：一类是从没测过，一类是原本测过、这次被拿掉了。

### 和场景覆盖不足的分界

看**基线有没有防护**，不看现在有没有。这张表判的是「要不要记一条测试退化信号」，决策点本身的状态照旧按现在有没有观测记：

| 情形 | 基线 | 现在 | 怎么记 |
|---|---|---|---|
| 新增的生产代码，没有对应用例 | 没有这条分支 | 无观测 | 决策点记无测试；**不记退化** |
| 本次修改的分支，测试没动也没补 | 有判别性断言 | 无观测 / 部分观测 | 决策点按现状记；**不记退化** |
| 已有或本次修改的分支，测试被删 / 禁用 | 有判别性断言 | 无观测 | 决策点记无测试，**并记 1 条退化** |
| 已有分支，断言被改松 | 有判别性断言 | 部分观测 / 无观测 | 决策点按现状记，**并记 1 条退化** |
| 已有分支，本来就一直没测 | 无测试 | 无测试 | 决策点记无测试；**不记退化** |

一句话：**测试退化只回答「基线有防护、现在没了或弱了」**；决策点「现在有没有防护」由观测状态回答。两者单位不同，同一处改动会在两处各留一条记录，报告用决策点编号交叉引用，不算重复计数。

一条信号要**计入**，必须三段同时成立：

1. **指得出具体改动**：哪个测试文件、哪条用例、哪个断言行
2. **证得出它原本在守本次的改动**：这条测试的断言引用了本次变更的生产符号，能对应到某个决策点
3. **证得出守不住了**：改动之后，该决策点的观测消失或变弱

缺任何一段，只作**提示**（信号表里「计入」填「否」），不进分布、不进定性。

| # | 信号 | 判定方法 |
|---|---|---|
| 1 | 断言弱化 | 同一断言行被修改：旧侧精确、新侧宽泛（`assertEquals` → `assertNotNull` / `assertTrue`；具体异常 → `Exception` / `Throwable`）。**不按断言行数减少判**——重构、抽公共方法、参数化都会让行数减少 |
| 2 | 测试文件删除 | 测试文件被删，且本次没有新增任何测试文件。排除重命名 / 搬移 |
| 3 | 新增禁用 | 新增**代码行**出现 `@Disabled`、`@Ignore`、`@pytest.mark.skip`、`@pytest.mark.skipif`、`GTEST_SKIP`、`TEST_IGNORE`。**不认裸 `skip` / `xit`**——会命中变量名、字符串和注释，`xit` 也不在 Java / Python 范围 |
| 4 | 断言被注释 | 删除侧有有效断言，新增侧把**同一段断言文本**注释掉了。新写一行注释提到断言不算 |
| 5 | 测例留空体 | `@Test` 注解还在、方法体从有内容变为空或只剩跳过。排除搬到父类 / 工具类、改成参数化包装 |
| 6 | 测试输入弱化 | **默认只作提示**：它指不出「被删的行」，不满足第 1 段，而且和步骤 3 的「改错会不会红」重复。只有能明确指认被削弱的断言与受损的决策点时才计入 |

**去重**：同一文件同一信号只记 1 条。

**与场景覆盖不足的关系**：两者单位不同（信号条 / 决策点），不构成重复计数。测试退化说「证据是被删掉的」，场景覆盖不足说「这条路现在没人看」——同一事实的两个侧面，报告里用决策点编号交叉引用。

## 计数规则

1. **断言质量低按用例计**：一个用例内有多条不判别断言也只算 1 个用例；不判别断言的条数在明细里单独报。
2. **测试脱靶是对象级提示**：命中时只作「场景覆盖不足」的附注，不并入决策点数。
3. **测试对象偏移与场景覆盖不足不重叠**：被架空的决策点记测试对象偏移，不记「分支未观测」。
4. **一处证据只归一个根因类型**：同一条信号同时支撑多个类型时，按根因归属计一次。
5. **单位不可混加**：决策点、用例、信号条是不同单位，分布表逐行标注，不要给合计。
6. **子类不进分布表**：子类只在 2.x 的问题条目里出现。
